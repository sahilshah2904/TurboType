# Alpha.9 laptop acceptance

Current target is laptop/desktop browsers and a physical keyboard. Phone/tablet support was explicitly canceled. User already reported alpha.8 points 5/6 working: typing/speedometer behavior, mistakes/Backspace, pause/resume/retry. Overdrive race music was accepted; alpha.9 preserves its exact WAV. New palette, Ignition menu music and scope cleanup require the focused checks below.

1. Refresh the laptop app and verify footer 0.1.0-alpha.9. Review metallic red/gold on Hub, Practice, Keyboard check and Settings; cyan should appear only in small light accents. Report hidden controls or uncomfortable contrast.
2. Enable sound and listen to Ignition for about 35 seconds (two loops). It should feel brighter and more energetic than Nightforge. Start a race and verify the separate 3–2–1 then the unchanged Overdrive track. Check volumes, pause/resume, mute and tab interruptions.
3. Resize the laptop browser between supported window widths (minimum 960 CSS px; representative checks 1024, 1366, 1440, 1920). Text/progress must remain intact, the track fill the width and the dial stay below the course.
4. Type a passage, deliberately mistype/correct with Backspace, pause/resume and retry. Confirm per-character feedback using the physical keyboard. Standard native IME composition still commits according to existing rules; no phone-keyboard test is required.
5. Compare Full/Low/Reduced motion, check audible loop joins, typing delay and repeated retries. Record laptop model, browser/OS, window size/zoom, effects and speaker/headphone details.

Developer work remains separate: distinct vehicle bodies/wheels, desktop performance/decode/transfer/memory measurements, final regression evidence and PR #4 review. These user observations do not alone close every Phase 5 gate. Screenshots/emulation cannot certify real fps or mix quality. The reported Samsung word-at-a-time caret behavior is out of scope, not claimed fixed.
